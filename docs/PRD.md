# 练伴产品需求（当前基线）

版本：0.5.1工作区基线；核对日期：2026-10-30。

本文件归纳已确认的产品方向。它描述目标及验收标准，**不表示全部功能已经上线**；交付状态见[DEV_STATUS.md](DEV_STATUS.md)，实现见[ARCHITECTURE_AND_AI.md](ARCHITECTURE_AND_AI.md)。

状态口径：下文“本地已实现”不代表云端或APK已同步；“待开发”与“待验收/待配置”分开列明。优先级P0为发布前必须解决的验证或数据边界问题，P1为下一轮核心体验完善，P2为后续扩展；不因本地测试通过自动改变发布状态。

## 1. 定位与用户

练伴是围绕用户长期训练记录提供建议的对话式AI私教。面向需要制定负重训练计划、记录饮食与训练、了解动作和获得陪训提示的健身用户。当前实时陪训聚焦平板杠铃卧推、高杠深蹲和传统硬拉；负重、自重、有氧、活动度资料分开标记。

产品不提供伤病诊断或保证动作安全；没有测得的数据、缺失的记录和AI建议不能冒充用户事实。研究带来的是候选知识/策略改进，需审核和评测后发布。

## 2. 信息架构与主流程

- 登录后，仅未保存过画像且未完成过引导的用户自动进入画像配置。已有画像直接进入首页，不因尚无计划或力量数据到期再次弹出设置；生成计划时仍须补齐有效资料。首次引导保存后生成整体周期计划草稿，确认后启用。
- 主页面聚焦私教对话及可拖动的Q版人类教练；四种性格使用独立提示词。视觉采用简洁黑白灰/蓝色，不使用绿色主色和动物教练形象。
- 侧边栏组织饮食、训练计划、训练记录与复盘、AI陪训、我/画像，以及健康数据、活动度、知识库等辅助入口。食物库位于饮食模块，动作库用于训练与计划选动作。
- 训练计划页保留AI生成和当前计划编辑；RM属于画像，训练历史与复盘属于独立记录模块。
- 较长填写模块先展示分组入口，进入后只显示当前小组；画像分基础资料、训练安排、力量评估、恢复限制和饮食习惯，力量再分胸/背/腿。切换和缩放保留本页输入，切换不自动保存或生成；提交校验全部必填并定位错误分组。健康恢复和营养目标同样按任务分组，原有授权、保存和确认操作保持独立。
- “训练工具与资料”提供趋势统计、个人进阶设置、译文审核和外部食品入口；动作库支持中英文展示。公开译文由管理员编辑审核，不等同科学知识审核。
- 训练完成→确认实际记录→基础总结→AI复盘与进阶评估→按受限策略更新下一次计划版本，展示差异/原因并支持撤销；营养校准及手动周期操作另行确认。

|---|---|---|

| PERF-01 | 常用资料缓存 | 本地 Redis 缓存提示词、画像事实、训练记忆与公开知识结果；用户隔离且加密，提交修改后失效、回滚不泄露、撤权/注销立即阻断访问，故障回到原数据源；不缓存 AI 最终回答或以缓存命中伪装真实评测，见 [REDIS_CACHE](REDIS_CACHE.md) |

| AGENT-01 | 对话式私教 | 可查画像、食物、动作、审核论文和知识；可提出饮食/计划/训练待确认操作；不能只口头声称已保存 |
| AGENT-02 | 可恢复执行 | 幂等请求、工具白名单、调用预算、执行记录和恢复；资料/授权变化使旧上下文失效，不能重复写入 |
| PLAN-01 | AI整体计划 | 按时间及完整三部位力量资料生成周期；各周每个负重动作必须有具体建议重量、组次、休息、目标余力及来源。区分同动作RM/实际表现/部位估计，估计标注首训校准；资料缺失不生成，模型空重量不接收；用户预览后确认，资料改变使草稿失效 |
| PLAN-09 | 每日目标与训练法 | 新草稿及各周训练日明确分组、简短目标、实际训练法和主项；计划按天显示摘要、展开动作，理由和周期按需查看。服务端校验分组覆盖/动作范围/方法组次；旧保存计划不伪造补充，旧未启用草稿需重建，进阶不能破坏所选方法 |
| PLAN-02 | 编辑与选择 | 当前计划可修改并形成版本；按多个关节动作与训练部位联动筛选。修改不能丢失未来恢复周或错误归并动作身份 |
| PLAN-03 | 渐进调整 | 依据确认的实际训练、余力/难度、不适和画像提出重量或次数变化，展示前后差异与理由；数据不足保持或追问，支持撤销 |
| PLAN-04 | 周期执行 | 周次、阶段、恢复周和完成进度可见；手动重练/减量/推进通过明确操作确认，整周达标后评估可推进；不因时间经过把漏练算作完成，不用其他计划同名训练日充数 |
| PLAN-05 | 常用动作候选扩充（待开发） | AI计划可从默认常用动作及用户维护条目中按器械、经验、训练类型和明确限制召回候选，保留来源/审核状态、ID与RM口径；不重新向默认列表塞回全部冗余动作 |

## 4. 统一业务规则

- **用户确认**：画像可从有依据的明确陈述沉淀；饮食、实际训练和计划启用需要确认。训练后进阶评估可应用新计划，但必须显示差异、原因并支持撤销；手动周期操作和营养校准需要明确确认，不静默改写。
- **伤病语义**：历史伤病不统一禁止AI评估；训练当下不适、疼痛或明确限制仍约束加重与建议。
- **资料优先级**：用户确认事实、器械/变式口径及程序约束决定可执行操作；论文/知识提供参考，不能覆盖权限、系统要求或业务校验。
- **产品策略**：进阶门槛、校准窗口、冷却、限幅和质控数字需明确标为练伴策略；不得直接归因于某篇论文或对所有人有效。
- **资料缺失**：不完整日记不等于热量不足，检测次数不等于实际完成次数，单次体脂/HRV不等于力量或健康变化。
- **回溯与隐私**：区分用户数据、授权摘要、AI建议与公开知识；删除、更正或撤回授权时，同事务使旧AI回复、草稿、复盘和后台上下文失效，并阻止处理中任务回灌。保留独立实际记录及已确认的目标数值；旧自动重试不能恢复已删记录。重新授权不恢复旧衍生内容，客户端忽略迟到响应。具体规则及边界见[PRIVACY_LIFECYCLE](PRIVACY_LIFECYCLE.md)，当前验证状态见DEV_STATUS。

## 5. 发布与非功能要求

- 客户端不持供应商密钥；HTTPS、登录、用户隔离及管理员权限有效。生产数据库和后端保持私有监听。
- 数值计算可复现；业务操作幂等；模型不可用时保留已保存的训练事实并提供恢复路径。
- 记录提示词/程序/模型/知识版本、实际工具与token；服务商未返回用量不能补算为零。费用以实际账单为准。
- 上线需隔离PostgreSQL迁移、备份/恢复、权限、真实模型、移动端和所改功能验收。本地测试或APK构建不能替代云端验收。
- 科学内容、动作判断和活动度有独立专业/真实用户验证要求；当前未完成时明确标记实验或待审核。
