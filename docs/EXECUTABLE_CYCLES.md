# 可执行训练周期

`days` 始终是当前周真实执行目标，兼容旧手机和训练记录。`cycle_schedule` 保存2–12周的完整周目标，每周有连续 `week`、`phase`、`purpose` 和完整 `days`；动作包含组数、次数、重量、目标余力与休息。`weeks` 继续保留文字说明。旧计划仅在读取时适配为相同周模板，不改写历史记录。

普通成人可以使用稳定的重复周。2026-03-17 [ACSM官方更新](https://acsm.org/resistance-training-guidelines-update-2026/)表示，复杂周期化对平均健康成人的结果没有一致额外收益；新立场声明 DOI 为 [10.1249/MSS.0000000000003897](https://doi.org/10.1249/MSS.0000000000003897)。不能把复杂阶段或每隔固定周减量作为所有人的必需条件。

## 执行与确认

- 记录保留当时 `plan_snapshot`；完成判断使用当时目标，热身组、辅助完成、不同负重口径和有不适的工作组不能算达标。
- 常规训练后评估保持自动、有版本、幂等、可撤销；所有正式训练日完成且恢复条件满足后，实际 `days` 切换到下一周。预先确认的恢复周会真正切换组数、次数、重量、余力和休息。
- AI只能修改本次动作的重量或次数，不能自由改阶段、组数、休息、余力、画像或RM。未来AI周目标不能预先提高基线组数、次数、重量。后续已通过进阶校验的负荷会延续到相同模板目标；有明确不同处方的恢复周保留其较低目标。
- 漏练不按日历跳周、不补课叠加。断训、近期不适、高用力或恢复不佳提示复核，可确认重复本周或降低组数后重启。重启有独立 `week_attempt`，不会重用当天旧完成记录。
- 周期结束标记 `cycle_complete` 与 `next_cycle.status=ready_for_review`，继续生成需确认的下一周期；保留 `previous_cycle_id`，不自动提高负重或重写RM。

`GET /api/plans` 附加 `cycle_status` 与可查看的每周目标。`GET /api/plans/cycle/current` 返回当前计划与状态。`POST /api/plans/cycle/actions` 接受 `request_id`、`base_plan_id`、`action`（`repeat_week`/`deload_week`/`advance_week`）。同请求同内容重试返回同事件，内容不同或陈旧版本拒绝。`/api/plans/changes/{id}/undo` 复用原撤销校验，只撤销仍为当前的那次变更。

AI草稿服务端保存完整周期，旧客户端与Agent仅提交 `name/days/generation_id` 仍能确认完整周期。编辑当前目标同步到对应周；纯重复模板更换训练日或动作时保留阶段目的重建模板。有真实周差异的周期不允许静默重建，须重新生成周期或明确提交完整周目标供复核。旧周期用稳定ID与训练显式plan_id匹配，不把缺失cycle_id的其他计划记录当作本周期完成。

模型只需输出一份基础 `days` 与紧凑 `cycle_blueprint`（周号、阶段、目的、base/recovery模板引用）；服务端物化完整周，recovery按产品策略减少工作组，逐周重新验证。无需模型重复最多504个动作目标；旧完整 `cycle_schedule` 输入仍兼容。确认草稿不能从客户端替换已验证的未来周。训练后LLM上下文仅提供当前周与阶段概览，移除训练记录中嵌套的整周期快照。

蓝图中的 `deload` 与 `recovery` 必须一一对应，避免显示“减量周”却没有改变实际组数。完整周目标接口仍允许用户明确给出其他减量方式。计划生成的输出预算为8192 tokens，以容纳最多7日的基础周与周期说明；训练后进阶仍只需小规模结构化输出。

## 产品策略与限制

`backend/policies/training-v1.json` 是 `training-policy-1` 的数值来源；RPE门槛、进阶幅度、14天断训复核、减量组数比例、余力默认值和时间估算都属于练伴产品执行策略，不能包装为ACSM或研究的一致阈值。计划与变更事件保留策略版本。

新AI周期生成前必须补齐胸/背/腿实际力量参考，各周负重动作均有具体起始建议和来源；无同动作RM时可根据实际表现或部位背景提出待校准建议，详见[STRENGTH_PROFILE](STRENGTH_PROFILE.md)。未来周自动加重及原进阶仍需有效同动作RM，器械增量及负重口径按原业务校验。每个AI周检查已有RM上限、动作一致性和时间估算。显式“只有/仅有/仅限”器械清单做确定性匹配；自由文本器械描述及身体不适范围仍需用户复核，服务不会把文本当成结构化医疗许可。近期不适动作暂停并提示复核，不据此诊断。用时是基于动作/组次/休息的粗估，不能保证每个人实际用时。

手机 `CycleSchedulePreview` 展开每周实际目标；`CyclePlanPanel` 显示本周进度、具体减量前后组数与确认操作，已在 `UserPlanEditor` 接入。没有手机安装或部署步骤。
