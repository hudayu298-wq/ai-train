# AI训练计划

> 版本说明：本文是早期AI计划流程。0.5新增可执行逐周周期、恢复周与确认推进，见[EXECUTABLE_CYCLES.md](EXECUTABLE_CYCLES.md)。当前PRD允许AI制定草稿、用户确认及编辑，交付状态见[DEV_STATUS.md](DEV_STATUS.md)。

首次未设置画像时进入引导 → 保存画像后自动生成 AI 草稿 → 检查周期、训练日与负荷 → 用户确认启用。已有画像或已完成过引导的用户重新进入时直接到首页，不因缺计划或力量资料到期再次自动弹出画像；需要补资料时在生成计划处提示，仍可从“我”主动编辑。未配置模型或调用失败时保留画像并提供重试，不用静态计划冒充 AI 结果。

生成只创建草稿，不覆盖已保存计划；确认保存产生新版本。画像或RM发生变化后，旧AI草稿需重新生成。

模型候选未通过结构、训练日、动作、训练法、重量或逐周校验时，服务端将具体错误反馈给同一计划生成流程，最多自动校正一次（总共最多两次模型请求）。校正前重新核对画像、力量、RM、训练和健康/活动度授权等修订，校正结果仍须完整通过原校验；无效候选不保存。服务端生成流程设置100秒预算，模型调用使用剩余时间；模型连接、配置等错误不盲目重试。最终仍不合格时显示具体原因和诊断编号，不用静态计划或自动填重量冒充成功。日志仅记录编号、校验阶段和规则代码，不记录画像或原始候选。

画像可独立选择全身或二至五分化与组次训练法；生成结果必须明确实际分化及每次的部位、目标、训练法和主项，不能只贴标签。计划按训练日摘要→展开动作组织，制定理由/热身恢复和逐周目标按需查看。当前周模板覆盖所选全部分组，天数不足提示调整；方法与后续进阶都要符合实际组次，旧未启用草稿需按新结构重建。格式、边界及接口字段见[TRAINING_PROGRAMS](TRAINING_PROGRAMS.md)。

当前动作范围：项目原有且有胸/背/腿参考方向的有效负重动作；自重及外部目录暂不参与自动计划。生成前必须补齐胸、背、腿各一个熟悉动作的近期实际表现；缺资料时明确提示回画像补齐，不调用模型。所有新生成周期的负重动作必须有正数建议重量，模型留空时拒绝该结果。依次使用同动作有效RM、同动作报告表现、部位力量背景估计，显示来源及首训校准标记；跨动作估计不换算或写入RM。历史伤病作为风险和动作选择上下文，近期实际不适动作从自动候选排除。原有器材、时长、RM上限和进阶约束保留。详见[力量画像](STRENGTH_PROFILE.md)。

## 画像与页面分工

- 画像：基础身体数据、目标、经验、具体目标、训练月数、每周训练日、开始时间、单次分钟数、器械、最小加重幅度、偏好、睡眠、恢复、伤病及可训练范围。胸/背/腿力量参考为必填；已有RM为可选的独立记录，不要求专门测试极限。
- 训练计划：根据画像生成、确认草稿、查看和修改当前计划。整体周期为2–12周（默认4周），包含每周阶段说明与可执行的一周安排；实际负荷根据完成记录逐步调整。
- 训练记录与复盘：记录逐组实际重量、次数、RPE、不适和恢复，查看AI复盘、历史与进阶结果。对话提取和已确认训练继续进入画像上下文；AI建议不写成用户事实。

修改当前计划保存为新版本，不覆盖历史。编辑期间计划被更新时返回409，需刷新。用户确认新的AI计划开始新周期；修改当前安排保留所在周期和周次。

## 训练后的进阶

1. 选择关联的当前计划训练日，核对实际逐组表现，明确确认是否完成该训练日。
2. 先保存训练事实，再独立请求AI复盘和进阶判断。模型失败时训练记录已保存，计划保留，可重试。
3. AI接收画像、可靠RM、当前计划、本次及上次同训练日表现、RPE和恢复情况，决定保持、增加重量、增加次数或减量。
4. 服务端限制：至少两个不同日期的同训练日均达标、两次RPE不高于8且恢复不差，才允许增加。一次只改重量或次数；最多每组增加1次，或增加5%重量。加重必须符合有效RM和器械增量。疲劳、高RPE可有依据地减量；本次疼痛动作不自动调整。上述为当前产品的保守约束，并不表示对所有个体适用。
5. 变化卡片显示原目标→下次目标、原因和计划版本，支持撤销最近一次自动调整。重复请求不重复加重；补录、旧版本训练和未关联训练不覆盖较新的计划。
6. 本轮全部计划训练日完成后推进周次；最终周完成时提示根据最新画像生成并确认下一周期。这里的周次按完成的一轮训练推进，不因日历过去就判定达标。

接口：`GET /api/onboarding`、`POST /api/onboarding/complete`、`POST /api/workouts/{id}/progression`、`POST /api/plans/changes/{id}/undo`。进阶与撤销均保存版本关系及训练来源，不能自动改写RM。

## 配置模型服务

复制根目录 `.env.example` 为 `.env`，填写服务商提供的配置：

```dotenv
AI_API_KEY=你的API密钥
AI_BASE_URL=服务商的API基础地址
AI_MODEL=你的账户可用模型ID
```

使用支持 `/chat/completions` 及 `response_format={"type":"json_object"}` 的服务。OpenAI基础地址为 `https://api.openai.com/v1`；其他服务以官方文档为准。模型ID不固定，按账户实际权限配置。

本机开发时每次调用读取根目录 `.env`。华为云 systemd 部署读取 `/etc/liftlab/liftlab.env`，修改后需要 `systemctl restart liftlab`。密钥仅存于后端；手机不会获取。`.env`已被Git忽略。不要将密钥提交到代码库或写进Flutter代码。

### DeepSeek 官方接口

```dotenv
AI_API_KEY=填写自己的密钥
AI_BASE_URL=https://api.deepseek.com
AI_MODEL=deepseek-flash
```

模型名以账户的 `/models` 查询结果为准。当前官方推荐 `deepseek-flash`；后端调用官方地址时显式关闭思考模式，使用 JSON 输出处理对话、训练计划和训练复盘。模型配置与视觉服务的 `VISION_*` 配置相互独立。

接口：`GET /api/ai/status` 返回配置状态；`GET/PUT /api/strength-profile` 查看/保存三部位实际表现；`POST /api/plans/generate` 根据已保存画像、三部位表现及可用RM返回草稿；`POST /api/plans` 确认保存（包括generation_id）。力量资料修改、到期、动作口径变化使旧草稿失效；旧版缺少力量修订的未启用AI草稿需重新生成，已保存历史计划不自动改写。

自动化回归测试使用模拟服务返回，不产生模型费用。真实生成需要有效API密钥、余额及网络；ChatGPT订阅和API计费分开。华为云已验证 DeepSeek 官方接口的模型访问、JSON 返回和私教回复结构；联调不写入个人档案。训练计划与训练复盘的实际效果仍需结合用户资料验证。

参考： https://api-docs.deepseek.com/api/create-chat-completion/ ， https://developers.openai.com/api/docs/quickstart 。
