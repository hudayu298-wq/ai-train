# 私有资料与 AI 衍生内容生命周期

更新：2026-11-02。实现与自动化证据见 [DEV_STATUS](DEV_STATUS.md)，生产同步单独验收。

## 数据变化后的行为

健康/活动度关闭保存或 AI 使用、删除或更正已有来源，以及删除饮食/训练记录时，服务在同一个锁定用户的 SQL 事务内推进 `privacy_meta/context_epoch`。同时使私有 Redis 缓存失效，并清理该用户已有的 AI 衍生内容。事务回滚会连同清理和修订一起回滚。

| 内容 | 处理方式 |
|---|---|
| Agent 运行与旧聊天回复 | 保留请求身份、原始用户输入和必要版本/用量；清空回复、上下文、模型消息、工具过程、引用与画像提取说明，显示失效提示 |
| 待确认操作、计划草稿、营养校准建议 | 清除旧 payload/说明；待确认状态失效，旧确认请求返回409，须重新生成 |
| 后台训练任务 | 取消；在调用之间及最终写入前复核修订，不能重排队或发布旧结果 |
| 训练复盘 | 清空旧 AI 复盘；生成前后核对授权、来源修订和训练档案修订 |
| 已启用计划、冻结计划、进阶事件 | 保留已确认的动作ID、重量、组次、余力、训练方法、日程和事件归属；删除生成时画像快照、旧 AI 理由及恢复建议等说明 |
| 实际训练/饮食 | 仅删除用户指定记录；其余事实保留。训练删除同时移除旧版镜像、相关执行项，并根据剩余记录重算比较摘要 |
| 旧请求重放 | 被删除饮食/训练的原请求ID保留内部墓碑，不能被自动重试恢复；用户以新请求明确重录仍可保存 |
| 账号删除 | 删除 owner 业务行、健康测量和 AI 租约；其他用户与公共资料不受影响 |

健康/营养来源失效时已校准营养目标同时失效，回到原确定性计算；活动度或单独训练变化不会删除独立营养目标。撤回 AI 使用授权与删除原始保存数据是不同操作，重新授权不会恢复已经清理的旧回复。

当前采取保守的 owner 级衍生内容清理，而不是猜测每句话依赖哪个测量。保留的用户输入、用户确认的数值目标与独立实际记录仍属于用户资料；本机制不等于删除所有文本中出现的相同词语。`privacy_meta` 与缓存内部元数据不导出。

## 并发与模型输入

`backend/services/privacy.py` 提供修订检查。Agent 检查点、异常保存、恢复、操作确认、计划草稿保存、复盘、进阶及后台任务复核当前修订；实际业务写入在同一用户行锁内复核待确认操作捕获的修订，避免“检查已通过、提交前刚撤权”的窗口。

模型只接收授权范围内的历史。没有授权/修订证明的旧聊天不回填到新提示词；缺少有效修订的旧未完成 Agent 任务需要重新提问。模型用计划视图仅保留确认目标；旧生成画像快照、训练记忆中的 AI 复盘不作为新事实再次输入。新鲜计划视图不会错误提示“说明已清除”。

Flutter 在成功的资料删除、更正或相关设置更新后推进页面修订：清除旧对话与私有聚合视图、重新读取，拒绝旧版本的迟到 GET/POST 结果。发送期间收到刷新仍会执行，未发送的输入框内容保留。其他离线设备、已打开的独立页面需联网重新加载；服务器会拒绝其旧草稿/任务写入。

## 验证和边界

`backend/test_privacy_lifecycle.py` 覆盖来源删除、撤权重授权、生成/确认/后台竞态、事务回滚、历史/运行/导出、账号删除、owner 隔离和旧请求防复活。`backend/test_context_consent_audit.py` 保留原撤权测试。Flutter 对话测试使用可控迟到响应验证刷新与发送竞态。隔离 PostgreSQL 使用同一组真实 SQL 路径，见 [POSTGRES_ACCEPTANCE](POSTGRES_ACCEPTANCE.md)。

最初复现了“删除健康来源后旧回复仍可读”和“撤权期间复盘仍落库”两个失败，修复后保留回归；首次 PG 全量的营养建议404/409不兼容也保留在验收记录。

此机制不撤回此前已发送给模型供应商的数据，不擦除用户已经下载/截图的副本，也不改写离线备份。备份包含私有数据，需受控保存并按运维留存策略过期；恢复旧备份前须重放后续删除/撤权决定，不能直接把旧备份投入业务。本文是工程生命周期审计，不宣称法律合规或独立渗透测试完成。公共 catalog/research/知识资料与 owner 私有内容分开处理。

本轮没有修改或重新激活本地V2知识。上下文与执行逻辑已变更，历史真实模型/发布评测只证明当时绑定；后续发布需重新核对源码指纹并运行要求的门槛，不能将本轮BM25业务回归当作80问神经检索或46题真实回答评测。
