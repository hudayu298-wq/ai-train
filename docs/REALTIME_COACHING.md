# 实时训练与语音教练

入口：动作 → 进入实时训练。范围为平板杠铃卧推、高杠深蹲、传统硬拉。

## 使用流程

1. 选择动作，阅读正侧面支架与镜头高度指引。
2. 开启相机；关键部位进入动作专用框，持续可见800ms后可准备训练。
3. 手动确认正侧面角度和被跟踪人物；框不自动验证角度、身份或杠铃。
4. 连接耳机，播放测试语音，手动确认听到。音频由系统路由，App尚不自动识别耳机。
5. 开始本组：实验性计次、语音报次、画面不可用提示。节奏提示默认关闭。
6. 结束后显示实验性次数。正式重量/组次需在训练页确认。

## 当前实现

- Flutter camera预览与帧流，Android使用camera_android的NV21，iOS使用BGRA8888。
- ML Kit基础模型STREAM模式，本地处理；摄像头帧不上传、不录制。
- 最多每100ms送一帧，上一帧未完成时丢帧；检测耗时超过500ms暂停判断。
- 关键点置信度和取景区域检查；低置信度、追踪丢失、帧间隔过长会重置动作状态。
- 深蹲用髋-膝-踝角、硬拉用肩-髋-膝角、卧推用肩-肘-腕角识别高位→低位→高位周期。
- 高低阈值、连续3帧滞回、周期至少600ms。阈值是开发初值，不代表标准幅度或动作质量。
- 可选节奏提示：周期短于1200ms提示下一次放慢节奏，需要教练验证。
- 语音不排队；说话时丢弃新提示，计次间隔至少1.8秒，普通提醒至少8秒，同句至少12秒。
- 后台或离页停止相机与播报，恢复后重新开启并确认角度。

## 平台与验证

Android/iOS需真机验证。Web展示拍摄模板，不能运行ML Kit实时检测。当前只支持竖屏正侧面，不支持同时录制、锁屏或后台分析。

iOS最低15.5，需要Mac/Xcode及原生依赖安装。Flutter桥接插件不是Google官方维护的插件。Web构建成功不代表移动端已构建成功。

## 下一阶段

- 真机检查帧格式、传感器旋转、预览坐标一致性、耳机路由、延迟、功耗与后台恢复。
- 健身房多人干扰：目标绑定、框外排除及切换检测；当前可能跟踪最显著人物。
- 个体校准、杠铃与器械识别、自动拍摄角度判断。
- 教练验证具体动作问题及提示时机。反馈优先在动作结束或下一次开始前，置信度不足不说。
- 本地保存摘要、用户确认记录；录像另行自愿开启，不默认上传完整视频。

三大项计次尚未经真实训练评测。开始于中间姿态、幅度不足可能漏计。卧推躺姿或器械遮挡可能导致拒绝判断。不能判断腹压、疼痛原因、肩胛状态或受伤风险。
