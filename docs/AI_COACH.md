# AI 私教与对话画像

Flutter `/app/` 首页现在只展示私教对话，左上角菜单打开侧边栏：AI 私教、饮食、训练计划、AI 陪训、我。饮食/动作库从对应页面进入，计划草稿保留按关节动作、部位选动作的流程。原根路径 `/` 是旧轻量预览，新的界面请用 `/app/`。

## 私教提示词

后端的 `backend/prompts/fitness_coach.md` 为共同系统提示词，身份为 LiftLab AI 健身教练。每次请求还会拼接所选教练在 `backend/prompts/coaches/` 下的独立性格提示词。侧边栏底部“私教提示词”可查看和复制实际生效的文字。修改文件后需要重启后端，当前版本 `coach-2.0`。四位教练与桌宠交互见 `COACH_PERSONAS.md`。

提示词规定简短中文交流、先回答再追问、以用户明确提供的资料为依据。无可靠 RM 不猜重量，未提供视频证据不声称发现动作问题。聊天不执行饮食、计划、RM、训练记录的写入，相关操作在侧边栏页面进行。

## 模型接入

与已有 AI 计划共用服务端 `.env`：

```dotenv
AI_API_KEY=填写模型服务密钥
AI_BASE_URL=服务商提供的兼容接口基础地址
AI_MODEL=服务商提供的模型名称
```

基础地址通常到 `/v1`，程序追加 `/chat/completions`。需要服务支持聊天和 JSON 输出。密钥保留在后端，不进入客户端。未配置返回明确的 503 提示，不生成假回复；HTTP、额度、权限、超时及不合规输出均返回可重试错误。API 需要独立可用的服务商额度。

视频截图观察仍使用独立的 `VISION_*` 设置；聊天模型接入不会自动启用可靠的视频动作纠错，见 `MOVEMENT_CONTENT.md`。

## 对话与画像保存

- SQLite `records` 保存 `coach_turn`（用户消息、回复、模型、提示词版本、画像更改及原话）和 `coach_profile`（已知事实）。
- 模型返回 `reply` 和 `profile_updates`；服务器验证允许字段、数值范围、原话是否存在于本次消息、数字是否匹配（支持米/厘米、斤/公斤换算），再原子保存整轮对话及画像。
- 未知字段保持缺失。年龄、身高、体重、代谢性别、目标、经验、每周天数补齐后自动同步到既有 `profile`，训练计划和当天营养目标可直接使用。伤病限制、饮食偏好、器械、训练偏好、时间安排也会保留。
- 新陈述只更改提取到的字段；手动更正立即生效。模型提取仍可能理解错误，聊天气泡显示记录结果及原话，可在“我”中修改。没有独立验证模型对所有假设、第三人称及中文表述的准确率。
- 有画像更新时客户端同步“我”和营养目标。AI 计划会使用器械、训练偏好和时间安排；草稿保存时检查相关画像有没有变化。
- 请求编号实现重复提交复用已保存结果。模型调用期间如其他页面修改画像或发送新对话，返回 409，避免较早回复覆盖新资料。
- 界面加载最近 40 轮，模型上下文携带最近 12 轮、当前画像、当天营养、最近计划/RM/训练记录和相关动作库信息；旧轮次继续保存在数据库。

对话及相关健身资料会发送给已配置的模型服务。仍是本机单用户版本，没有登录和用户数据隔离；用户画像中的限制不等同于医疗诊断。

## 接口

| 接口 | 用途 |
| --- | --- |
| `GET /api/coach/status` | 服务是否已配置，不返回密钥 |
| `GET /api/coach/prompt` | 查看实际提示词 |
| `GET /api/coach/messages` | 最近对话与当前画像 |
| `POST /api/coach/messages` | `{request_id, message}`，返回回复及已写入的更改 |
| `GET /api/coach/profile` | 完整或部分事实、缺失字段、字段名称 |
| `PATCH /api/coach/profile` | 手动更改部分字段；空文本清空对应偏好，null 不更改 |

## 已验证与限制

回归测试覆盖部分画像、完整画像同步、手动更正、保留未提及字段、引用原话验证、非法提取不落库、重复请求、并发修改、模型请求结构、无密钥错误，以及对话输入重试、画像气泡、侧边栏导航。使用模拟模型响应完成协议测试；真实模型的对话质量与提取准确率仍需配置密钥后实测。Android 安装未更新。
