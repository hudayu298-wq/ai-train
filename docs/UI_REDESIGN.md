# Q 版教练与界面整理

## 当前设计

- 四位角色统一为 Q 版成年健身教练，以发型、服装、眼镜和腕表区分，移除动物/机器人外形。保留四套性格、独立提示词、拖动、思考、呼吸浮动、轻弹鼓励和提醒互动。
- 界面采用黑白灰，主按钮为近黑色，导航选中为中性灰，蓝色用于数据进度和焦点。角色服装保留原有身份色；没有绿色主题或绿色拍摄就绪框。
- 全局统一字体层级、细边框、留白、卡片、表单、按钮、抽屉与底部选择面板。
- 聊天保留清晰的姓名与消息；移除用户气泡中的重复姓名。首页连接状态改为紧凑状态条，配置说明和画像说明按需展开。已有历史记录时不重复插入欢迎气泡。
- 教练在待机时只显示角色与操作，减少气泡干扰。左侧菜单压缩成紧凑品牌区域与导航。
- 用户画像移除与编辑表单重复的整段数据展示；RM 录入收进可展开区域；当天营养在宽屏显示四项指标，手机两列，极窄内容区单列。
- 动作分类入口保留，缩短入口说明。旧的根路径 HTML 预览同步使用黑白灰与蓝色。

## 文件

- `mobile/lib/ui_theme.dart`：统一颜色与组件主题。
- `mobile/lib/coaches/coach_pet.dart`：Q 版人类教练素材展示及互动。
- `backend/data/coach_personas.json`：人物外观标识、颜色及离线文案；运行 `scripts/build_coach_personas.py` 同步 Flutter。
- `docs/assets/human-coaches.png`：四位教练渲染预览。
- `docs/assets/ui-chat.png`、`ui-coaches.png`：手机尺寸的聊天与选择界面渲染预览，使用模拟空数据与未配置模型状态，非真实模型对话截图。

界面预览已通过 Flutter 控件渲染检查，确认四位角色、中文、图标、选择面板和聊天输入框显示正常。业务回归覆盖现有对话、切换、画像、饮食、计划、分类和提醒流程。手机仍遵循“暂不更新手机”的要求，只构建安装包。

## 2026-10-17 角色重制

四位教练换为内置 image_gen 生成的透明 PNG。男教练穿运动背心，女教练穿长瑜伽裤，强化肌肉轮廓和五官细节。头像聚焦脸部，选择卡加大全身展示。完整素材清单与提示词见 `COACH_ART.md`。

## 2026-10-25 Taste Skill 核心界面调整（本地）

用户指定的 `npx skills add https://github.com/Leonxlnx/taste-skill --skill "design-taste-frontend"` 已执行。Windows 原有 npx 包装器绑定旧 Node，首次报 ES Module 错误；改用 Codex 自带 Node 24 执行同一 npx 入口后安装成功。技能保存在 `.agents/skills/design-taste-frontend`，来源及计算哈希保存在根目录 `skills-lock.json`。

按技能的 App 流程抽取并选择 **Achromatic ledger**，seed **1596384843**，保留既有黑白灰/蓝色及四位人类教练素材，没有重新抽取方向。选择理由：每天反复使用的私人训练工具需要先看清事实和下一步操作。品牌特征为四位教练、确认式操作及营养目标对照，不引入虚构成绩或仪表盘数据。

| 界面 | 首要问题与处理 |
|---|---|
| 首页私教 | 从哪里开始对话：显示教练身份、真实人格问候、训练/饮食/复盘快捷话题；点击只填入可编辑输入框，不自动发送或保存 |
| 训练计划 | 这次怎么练：当前周次、版本、训练日、目标重量/组次/休息清楚分组；训练依据可展开，风险提示仍直接显示；新增既有训练记录流程的入口 |
| 饮食 | 已记录摄入与目标差多少：指标提前，带单位与真实比例，完整度与不完整日记提示继续保留；不把设备热量叠加目标 |
| 动作/食物库 | 如何找到条目：搜索常驻、宽屏筛选网格、手机筛选展开区、结果数量及无匹配提示；分类、原ID、语言回退与审核边界保留 |
| 我/画像 | 哪些信息需要完善：宽屏将年龄/身高/体重并排，手机顺序排列；保留原校验及保存反馈 |
| 登录 | 如何进入本人空间：桌面品牌/表单分栏，手机单栏；支持显示密码；普通邮箱登录不再展示仅注册或微信建号需要的邀请码 |

全局采用 8px 面板、6px 控件、清晰文字层级、较深辅助文字及 44px 操作目标。桌面宽度至少1100px时显示240px常驻导航，较窄屏幕使用抽屉；内容区按本地可用宽度布局，训练记录不再无限拉宽。响应式列使用稳定的控件树，避免切换宽度丢失表单草稿。

新增 `mobile/lib/ui_components.dart` 统一内容框、页面简介和响应式列/字段网格；深层业务页面继承主题，本轮没有逐一重写其业务交互。现有API足以提供本轮界面数据，**没有后端接口、数据库、提示词或知识版本修改**。

内置未经修改的 Noto Sans SC Regular，减少 Web 首屏依赖远程中文回退字体的问题；字体为8,331,336字节，会增加客户端资源体积。来源、SHA256及许可见 [字体说明](../mobile/assets/fonts/README.md)。OFL随应用打包并登记到Flutter许可证注册表。按钮、标签和星期选择片共用该字体；罕见缺字仍可能触发平台回退。

## 2026-10-26 大模块内的分组填写

沿用Taste Skill的Achromatic ledger视觉和已加载字体，不重画主导航。较长表单先显示带说明的分组列表，进入后只呈现当前组，可返回列表、前后切换；没有将下一组当作已保存或已完成。

| 模块 | 内部分组 |
|---|---|
| 用户画像及首次引导 | 基础资料、训练安排、力量评估、恢复与限制、饮食习惯 |
| 力量评估 | 胸部表现、背部表现、腿部表现；部位按钮与画像分组按钮明确区分 |
| 健康与恢复 | 授权与隐私、近期趋势、添加测量、恢复反馈、记录管理；未授权保存时隐藏需保存的录入入口 |

“我”里的可选RM和已确认训练档案按需展开。首次引导、健康、营养使用800px限宽，手机单列，保留正常滚动。训练工具和研究页原来已有内部导航，沿用其分工。

`ui_components.dart`新增`ModuleSection/ModuleSections`，按稳定分组标题保持控件身份，Offstage只隐藏当前组以外的布局/语义，ExcludeFocus排除其键盘焦点，TickerMode暂停隐藏动画；不使用会保留最高表单高度的IndexedStack。移除当前可用分组时安全回到列表。全部表单仍参与画像保存校验，错误打开相应组；力量校验同时定位到部位。切换/缩放保留本页输入，不新增本机持久草稿，关闭或刷新仍会丢弃未保存内容。

没有新增接口或改变字段口径。画像仍统一保存；健康保存/AI授权、测量和恢复记录、营养设置及建议确认仍按原有独立操作提交。健康首次加载或手动刷新不再误显示“已保存”。最新测试、三档截图、构建和未验收项见DEV_STATUS。
