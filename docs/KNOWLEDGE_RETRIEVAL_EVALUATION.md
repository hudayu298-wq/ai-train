# 知识检索与发布评测

## 范围

现代检索目前作用于基础知识包：动作/关节/肌肉/骨性标志、运动营养规则、训练周期策略和活动度测量原则。论文证据的采集、审核和发布仍是独立流程，不应将本报告表述为整个论文库的统一检索成绩。

“SOTA”是需要与外部系统在统一条件下比较的结果。本项目实现可复现的混合检索和发布门槛；没有全球领先或临床有效性的证明。CPU 量化模型用于当前服务器资源约束，不代表选用了当前全球最强模型。

## 检索链路

1. 固定知识包版本与内容摘要，先过滤撤回的节点和来源。
2. 按结构化事实生成有来源的短片段，保留节点与来源关系。
3. BM25 中文字词召回与本地语义向量召回。
4. RRF 融合候选；按父节点聚合后使用交叉编码器重排，再等权融合召回排序与重排排序。复合问题的某条依据只回答其中一部分时，不因单条重排绝对分数低而直接删除；整个问题无相关候选时仍拒检。规则不读取题库标签或必需节点ID。
5. 返回真实命中的节点、片段和引用 ID。语义运行失败会显式降级并记录实际管线；降级结果不能冒充神经检索评测通过。

向量和重排在服务器本地运行；不向外部嵌入服务发送用户画像或健康序列。模型文件按固定提交、大小和 SHA256 校验，数据文件不执行远程 Python。小知识库使用精确距离；PostgreSQL 安装 pgvector 后使用受版本和节点范围约束的精确距离查询，未安装时明确报告 JSON/NumPy 精确计算。

2026-10-28检索策略为`hybrid-retrieval-20261028-v3`。复合问题按独立问句拆成最多3部分，不拆实体列表；每部分最多保留两条不同父节点的实际语义命中，进入共同候选池，只有实际重排支持的条目才参与最终覆盖保留，其余位置按整体融合排序填充。拆句、候选数和返回预算均固定，不读取题库或指定答案节点。重排按片段长度组成批次并恢复原候选顺序，减少padding而不交换节点身份或分数。先在20题dev核对，再执行原冻结test和完整模型评测；旧报告保留。是否激活及实际指标见[DEV_STATUS](DEV_STATUS.md)，算法调整本身不是发布通过声明。

## 两层评测

### 检索相关性

固定文件 `backend/data/knowledge_retrieval_benchmark.json` 包含 80 个项目内编写的问题，20 个 dev、60 个 test。相关性标签仅用于评分，不传给模型。对比真实 `legacy`、`bm25`、`dense`、`hybrid_rerank` 四种管线。

主指标为 test 的 Recall@5、MRR@5、nDCG@5，同时保留各分类、逐题回归、关键比较节点覆盖、拒检、降级次数以及 p50/p95 实测延迟。dev 先执行，test 延迟通常对应热缓存状态，不能直接外推手机或云服务器延迟。

预先固定的发布门槛：

- test Recall@5 不低于 0.85。
- Recall、MRR、nDCG 均不低于 BM25 基线。
- 所有关键题必须同时检出其必需节点。
- 三个未覆盖领域问题均拒检；这只验证空检索，不代表生成回答的医疗拒答已经验证。
- 真正运行了嵌入与重排，无隐式降级；没有异常、撤回结果或缺失的目标节点。
- 数据集、语料、模型、检索策略及撤回列表在运行期间不变。

不得为了让本次 test 通过而修改标签或门槛。算法优化应先使用 dev，并保留前后结果；已被反复观察的 test 仍属内部回归集，需要后续独立专家和新留出题做泛化验证。

### 回答与引用

`backend/data/knowledge_benchmark.json` 的 46 题涵盖基础事实、营养定量规则、周期产品策略、ROM 边界和未知个人事实。每批在“模型自身知识”和“提供知识包”两种条件下使用相同问题、选项、结构化输出约束并交替执行顺序。

评分检查答案、拒答、引用是否实际返回且确实支持该题。原有 90% 正确率、无事实回归、关键题全部正确、引用有据及同一实际模型的门槛继续保留，并增加检索评测必须通过。选择题成绩不能替代自由文本、真实用户、专业审阅或伤病场景验证。

评测输入保留每次实际命中节点的全部结构化事实、概述、适用人群、局限和真实引用ID/链接，省略重复的关系邻居、匹配片段及展示元数据，避免预算被重复内容占用。评分器仍使用完整原始检索结果；不按正确答案选择事实，不增补未命中依据，不改变题目、两条件问题/选项/输出schema或评分门槛。

输出明确要求顶层仅含`items`。对供应商额外回显的唯一固定封装字段`type: "json_object"`可移除并记录`format_normalizations`；其他额外字段、错误类型和逐题格式仍严格拒绝，答案/拒答/引用内容不修改。原始格式失败记录保留，不能用这一格式兼容把错误答案计为正确或复用旧指纹报告。

## 管理与发布

- 最新内置 v2 只注册为候选，不自动取代已冻结 v1。
- 候选导入 → 管理员审核 → 真实检索及回答评测 → 管理员发布。
- 管理员可单独提交检索任务：`POST /api/knowledge/bundles/{version}/retrieval-evaluate`。
- 完整知识评测：`POST /api/knowledge/bundles/{version}/evaluate`，结果内嵌检索报告。
- 已有仍有效的真实通过检索报告时，管理员可用`evaluate?retrieval_evaluation_id=...`选取；排队、worker、QA入口及最终发布均核对原有语料/题库/撤回/模型/管线等绑定。保留原检索时间及分数，QA报告标记`retrieval_evaluation_reused`，46题双条件仍全部调用真实模型重新执行；不能用缺失、失败或过期报告替代检索门槛。
- 索引当前版本：`POST /api/knowledge/index`。
- 这些任务由研究 worker 执行；检索评测与完整评测共享每天最多两次完整评测的预算。
- 发布时再次核对语料、数据集、模型清单、检索策略、撤回列表、QA 运行代码与基础版本。只有两个层面的真实报告均通过才可激活；失败报告仍保存供排查。
- 来源撤回立即作用于搜索、关系邻居和已固定版本的引用验证。历史原始知识包导出仅向管理员开放，供审计使用。

## 尚不能从这些评测得出的结论

- 不能证明全身解剖覆盖完整、营养处方适合疾病人群或 ROM 自测达到了临床测量精度。
- 不能证明二维录像推断肌肉激活、精确关节角度或损伤诊断的能力。
- 没有外部盲测、训练收益试验或并发资源测试时，不能宣称全球 SOTA 或默认适合当前 2GB 生产服务器。
