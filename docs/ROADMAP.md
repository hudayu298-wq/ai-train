# 开发路线

## 已建立的工程基础

- [x] 用户画像、规则模板、计划版本
- [x] 训练记录与饮食记录 API
- [x] 浏览器预览与本机持久化
- [x] 媒体上传与未接入状态
- [x] Flutter 客户端业务入口

## 接下来优先交付

1. 专业审核三大项模板，按训练经验、可用时间和器械分层；加入活动水平与饮食偏好。
2. 食物数据库导入：授权来源、单位、生熟状态、食谱、审核版本。
3. 食物识别适配器：图片 → 候选食物与待确认份量 → 数据库匹配 → 用户确认后保存；不能直接信任生成的营养数字。
4. 视频技术验证：MediaPipe 关键点、质量门槛、动作阶段与次数；独立验证杠铃追踪。
5. 每个动作的纠错规则由教练定义；用不同用户测试集评估误报、漏报、拒绝判断率。
6. 周度调整：体重趋势、执行率、疲劳、RPE、不适；用户确认和版本追踪。
7. 多用户：登录鉴权、PostgreSQL、对象存储、异步任务和用户级数据隔离。

## 模型结果约定

食物识别返回候选 `food_id/name`、份量建议、置信度和追问；营养由确定性程序算出。低置信度必须支持手动更正。

动作分析返回 `exercise_variant`、拍摄质量、次数、按时间区间定位的问题、证据、规则版本、可判断与不可判断项。不要仅返回一个总分。当前 API 故意不返回分析字段。

## 发布门槛

专业审核的内容、真实媒体验证、用户权限隔离、删除和备份恢复、设备评测、成本指标、每类动作问题独立评测。当前开发版不能直接对公网发布。
