# 逐组执行与目标对照

2026-10-24，本地0.5.1增量。参考wger“计划目标与实际记录分离”的公开设计思路，以现有Flutter/FastAPI代码独立实现，没有引入或复制其源码、素材或依赖。

## 使用入口

记录与复盘 → 记录本次训练 → 选择计划训练日（或手工添加动作）→ 开始逐组训练与休息计时。

- 逐组页面只修改本机草稿；每组实际重量、次数、RPE由用户确认，RIR与不适可补充。计划目标只作单独参考，不预填成实际训练事实。
- 确认本组后开始休息，按实际经过的时间记录；计时到点只提示，不自动确认下一组。用户点击继续才结束休息，最后一组不制造训练后的“组间休息”。离开页面会取消计时，未结束的休息不补造数值。
- 返回训练日志后仍须核对并点击完成训练保存。没有记录的组须继续填写或由用户移除；不因打开页面、倒计时或计划组数自动勾选整日完成。网络重试继续沿用既有幂等请求与草稿机制。
- 手工及现有计划记录流程当前限于原有负重训练模型；本次没有扩展自重/有氧计量模型。

## 保存后的对照

服务端从现有plan_snapshot计算逐工作组target_comparison（workout-rules-2），包含目标/实际重量、次数、RIR、休息及可比较字段差值，标明额外组或未记录组。热身组不占计划工作组位置，未记录不能等同于确定漏练，也不自动判断达标或推进。

已关联计划并进入逐组执行时，通过服务器创建**开练冻结快照**，本机草稿保留execution_id，后续计划修改不会改变本次目标。快照只包含计划目标、版本、周期身份，不附带画像/健康摘要；账户隔离、开练编号重试幂等、一次开练不允许重复创建不同训练记录。冻结构成当天训练，日期不可随意修改；历史补录仍走普通日志。未进入冻结流程的旧客户端或手工记录，继续使用最终确认保存时的计划目标并注明依据。未绑定计划不虚构目标，未知重量不当作零；修改负重口径或注明器械编号时不计算目标重量差值。

复盘页面同时展示目标/实际的重量、次数、余力和休息。既有历史记录没有新汇总字段时继续按旧界面显示，不批量重写事实。

## 近28天统计

training_memory.last_28_days包含日期范围、记录次数、训练天数、工作组，以及按动作ID+重量说明+负重口径+器械编号分组的次数、训练量与不适组数。沿用现有owner隔离和history中旧训练去重。热身不计入工作组，不跨器械混算，也不从训练量推导RM、热量或肌肉增长。

统计在“我”的训练档案可见，并随既有模型上下文供Agent参考；未调用模型也能计算。它不是自动进阶策略，既有疼痛、余力、授权及计划确认约束保持有效。

## 2026-10-24 其余六项扩展（本地已实现并自验收）

### 开练快照与交替执行

- 日志选择计划日后进入逐组执行，将以同一开练编号创建或恢复服务器冻结目标；返回或刷新草稿仍引用同一快照。保留实际草稿、解除冻结后可重新关联；旧冻结记录不被删除或改写。开始冻结仅适用于当天，完成保存会核对日期、计划和训练日；同一开练快照只能用于一条事实记录。
- 每个动作“执行编排”可设普通组或交替组1–5；同组2–4个动作轮流执行，如A1/B1/A2/B2，组数不等时保留剩余组。动作/组的实际值仍绑定原始位置，不因顺序变化错写。分组随草稿恢复，并保存到训练记录的execution_groups。
- 休息依旧由用户手动结束，交替编排不会自动缩短休息或判定安全；不是无休息的强制超级组处方。
- 冻结后若当前计划已发生变化，本次事实照常保存，但进阶返回held，不覆盖新计划。

### 训练工具与资料

侧栏新增“训练工具与资料”：

1. **趋势统计**：28/84/180/365天，按周、cycle_id及主要肌群显示工作组柱条。缺失记录周显示0，不等于确认未练；肌群按标签可多重归属，不能求和冒充实际总组数，也不代表实测肌肉激活。来源分类仍保留原审核边界。
2. **进阶设置**：本账户可关闭评估、选择只加重量/只加次数、将最低可比较日期数从2收紧到最多6、RPE上限5–8、加重比例上限0–5%、次数变化0–1。只收紧全局产品边界，疼痛、恢复、器械可比性及RM检查不可关闭。不发布全局策略、不改变既有知识门槛；修改设置不直接修改计划，已完成的幂等评估不自动重算。
3. **译文审核**：中英文动作名/教学描述，明确同意公开后提交；管理员才可审核发布、驳回和撤回。审核绑定当前条目内容指纹，源条目变化后旧稿不能发布，已发布译文也失效回退。保留原始来源/别名、用户自定义条目优先；动作库可选择中英文。这里的编辑审核不等于科学内容、知识或策略发布审核，采用独立catalog_lock，不触碰知识活动指针。
4. **外部食品**：Open Food Facts只读条码查询，固定官方域名、有限超时、全服务10次/分钟额度及24小时本人缓存；无自动重试、无图片下载、无外部写入。支持v3.6嵌套nutrition结构及旧nutriments标签结构，仅接受明确每100克、来源为包装/厂商且单位正确的完整营养值；拒绝估算、模糊值、每份/每100ml口径和缺失字段，不用0补齐。

食品在用户核对并确认后保存到本人external_food，保持ODbL / DbCL归属和来源URL，与公共catalog分开；Agent可搜索并提出待确认饮食操作，最终按确认份量确定性计算。查询/保存食物本身不会记录吃过；其他账户查不到本人保存项。商品标签数据不等同于专业营养审核。
