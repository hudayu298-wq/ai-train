# 营养定量规则与反馈闭环

规则版本：`nutrition-2026.10.22-v1`。核对日期：2026-10-22。实现：`backend/services/nutrition.py`、`backend/nutrition_guidance.py`；知识卡由同一注册表生成，入口为 `backend/services/knowledge_nutrition.py::install_nutrition`。

本功能提供健康运动成人的饮食计划起点与小步趋势建议。公式、共识和产品策略的来源分别标注；本产品未做独立临床验证。怀孕、哺乳、进食障碍、肾病等需要治疗性饮食的情况应先由专业人员评估。选择“需要专业人员评估”后停止自动目标。公式研究的人群范围与产品允许输入的范围不完全相同；超出研究年龄范围会显示提示，自动校准采用更窄的适用范围。

## 计算与默认值审核

| 规则 | 执行值与单位 | 性质、依据及限制 |
| --- | --- | --- |
| 静息能量 | `10×体重kg + 6.25×身高cm − 5×年龄岁 + 性别常数`，kcal/日；常数为男性+5、女性−161 | [Mifflin等1990年原始研究](https://pubmed.ncbi.nlm.nih.gov/2305711/)的简化公式；498名健康受试者，19–78岁。它估算静息能量，不能当作实际测量值或个体每日消耗。公式性别来自现有画像。 |
| 活动系数 | 默认1.4，可设置1.2–2.2，无量纲 | 默认值和设置范围是产品策略；没有宣称Mifflin论文给出这些活动系数。训练天数和设备活动热量不会自动改变系数。 |
| 目标调整 | 减脂默认−250，范围−500至0；增肌默认+200，范围0至400，kcal/日 | 保留原产品起点并开放明确设置；不是通用处方或论文结论。留空按当前画像目标选择默认值。画像目标变化而保存的显式调整不再匹配时，停止自动目标并提示重设。 |
| 蛋白质 | 默认1.6，可设置1.4–2.0，g/kg/日 | [ISSN 2017立场文件](https://pubmed.ncbi.nlm.nih.gov/28642676/)支持多数运动成人的1.4–2.0范围；1.6这一默认点是产品选择，不能把范围当作每个人的最优值。 |
| 脂肪 | 默认0.8，可设置0.6–1.2，g/kg/日 | 产品宏量营养分配策略，没有借用蛋白质来源证明脂肪阈值。 |
| 剩余碳水 | `(目标热量−蛋白质g×4−脂肪g×9)/4`，g/日 | 产品使用常规4/4/9近似分配；宏量营养克数取整可能造成小量热量差。食物热量仍使用食物数据库值，不能用此式替换每项食物数据。蛋白质和脂肪已超过可用热量时停止目标，不把碳水截为0来掩盖冲突。 |
| 自动计算范围 | 女性至少1200、男性至少1500、至多4500，kcal/日 | 产品自动计算边界，不是个人的安全摄入下限，也不是NIDDK统一处方。超出边界时返回`needs_review`，不会强制截断后生成目标。BMI<18.5且目标为减脂时同样停止。 |

原先 `nutrition.target` 中活动系数1.4、能量−250/+200、蛋白质1.6、脂肪0.8的角色现已分别公开。食物克数/每100克营养换算继续使用Decimal和四舍五入，现有食物来源、状态、份量确认、请求幂等与仅当天记账契约均保留。

## 趋势校准的数据与授权

以下观察窗口与阈值都是产品策略，没有宣称已由临床研究验证：

1. 用户已授权保存健康数据，并在营养设置中单独开启`calibration_enabled`。该授权只允许此确定性校准使用已有体重及饮食记录；不要求也不自动开启AI上下文授权。
2. 用户明确确认适用情况，年龄19–78岁且BMI为18.5–40。更高/更低BMI和其他不适用情况停止自动校准，保留学习与记录能力。
3. 只看上海时区最近14个已结束的自然日。14天都必须被用户标记为完整、且每一天有食物记录。缺餐、无记录、未完成或完整状态被新增/删除食物破坏时，不能视为零摄入或能量不足。此功能不增加历史补记API。
4. 窗口内每条食物份量须已确认，来源为称重`weighed`或标签`label`。照片估算、`ai_confirmed`或未知份量不能支持此自动校准。
5. 体重须为非估算的kg数据，方法为体重秤或自报；以provider、device、method、conditions、source_app完全相同的一组观察值计算。若存在多个来源，选择覆盖天数最多的一组，同数时稳定排序选择，不合并设备。每天重复称重取日中位数，两个7日窗口各至少5个有效日。
6. 平均摄入与当前有效热量目标相差不得超过15%；否则提示先核对执行与份量。两周体重均值的周变化超过绝对值1%时停止自动建议，提示先排除水分与健康因素。

“完整”和自报体重是用户声明，不能证明不存在漏记或测量误差。产品保留来源及记录ID、汇总与数据指纹，不能将此流程描述为真实代谢测量。

## 反馈与确认

两组7日平均体重的相对差值作为本轮每周趋势。减脂观察区间为−0.75%至−0.25%/周，增肌为+0.1%至+0.25%/周。位于区间内维持目标；高于区间建议−100 kcal/日，低于区间建议+100 kcal/日。每步100、累计偏离当前公式基线最多300、两次确认至少间隔14个自然日，均为保守产品策略。平均摄入、同源周均值和当前目标会展示给用户，建议只调整能量并重算剩余碳水，蛋白质和脂肪按设置保留。

不使用7700 kcal/kg等固定系数从短期体重反推精确维持代谢。手表活动热量不加到饮食目标，也不从已记录食物中扣除。[Shcherbina等2017年设备研究](https://pubmed.ncbi.nlm.nih.gov/28538708/)说明当时测试设备的能耗估计存在误差，不能推出所有当前设备的统一误差比例。本产品的“不叠加”是避免重复计算和过度推断的产品约束。

建议生成后状态为`pending`，不会改变当天目标。用户确认才写入有效目标；待确认建议48小时过期。确认在用户锁和同一数据库事务内重新检查授权、画像、设置、当前目标、观察窗口、完整状态、食物与体重数据指纹，任一变化即409拒绝，要求重新评估。创建请求按request_id幂等；相同确认request_id重试只返回原结果，不重复应用。其他用户看不到或不能确认该建议。

保存新设置会清除旧校准目标；画像数值或目标变化时基线指纹失配，自动回到新画像的公式估计。撤销校准授权或健康存储授权后，已确认校准不再作为有效目标。原确认记录保留为用户私有审计历史；幂等重试不会恢复被撤销的目标。

[NIDDK工具说明](https://www.niddk.nih.gov/health-information/weight-management/body-weight-planner)将其成人体重规划工具排除未成年人、孕期及哺乳期。本产品参考其适用边界，不声称实现NIDDK动态代谢模型，也不引用其名称证明本产品有效。

## API与界面接入

在现有已认证API挂载 `app.include_router(nutrition_guidance.router(connection))`。所有个人记录使用现有Store的owner作用域，无新增共享用户表或客户端owner参数。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/nutrition-guidance/rules` | 定量规则版本、单位、来源、适用人群和产品策略标识 |
| `GET /api/nutrition-guidance/settings` | 读取本用户目标设置 |
| `PUT /api/nutrition-guidance/settings` | 显式保存完整设置，数值校验并使旧校准目标失效 |
| `GET /api/nutrition-guidance/target` | 有效目标、公式输入、计算步骤、来源、提示、规则与来源清单 |
| `GET /api/nutrition-guidance/calibration` | 只评估数据资格；不足时解释原因，不生成建议 |
| `GET /api/nutrition-guidance/suggestions` | 本用户最近20条建议 |
| `POST /api/nutrition-guidance/suggestions` | body为`{"request_id":"..."}`；资格满足才创建待确认建议 |
| `POST /api/nutrition-guidance/suggestions/{id}/confirm` | body为独立的确认`request_id`，复核后生效 |

`nutrition.summary(db,day,profile)`已使用`effective_explanation`计算目标并提供`target_basis`；原当天饮食、比较值以及使用该摘要的私教上下文共享相同有效目标。其他调用方可使用`effective_target(db,profile)`。`target(profile)`仍为默认公式估计助手，不包含用户设置或已确认反馈；需要实际目标时必须提供db。

Flutter入口为`NutritionGuidancePage(request: request)`，展示有效目标、计算过程、来源、设置、数据资格和建议确认，沿用现有蓝紫主题。设置只有保存后生效；确认前页面不宣称目标已改变。服务端是授权、失效与边界检查的最终依据。
