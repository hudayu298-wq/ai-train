# 训练记录、画像沉淀与复盘

## 使用流程

1. 侧边栏 → 训练记录与复盘 → “记录本次训练”。可关联当前计划训练日，并按关节动作分类选择实际完成的动作。预填的计划目标需要用户确认实际表现，不视为已经完成。
2. 逐组填写重量（按动作库负重口径）、实际次数、RPE、不适；可填写日期、用时、动作感受和整体恢复情况。同一次训练支持多个动作，不把计划安排视为已完成。
3. “完成训练并生成复盘”先保存确认记录和基础复盘，再尝试生成当前性格教练的 AI 复盘和独立的进阶评估。未配置模型、超时或生成失败不会回滚训练；复盘可在当前页或历史重试，进阶失败时当前页提供重试。
4. “我 → 训练档案”显示累计记录、近28天训练天数、累计组数、各动作最近表现和近期不适。训练历史可展开每组记录、用户感受、基础总结和 AI 建议。
5. 后续私教对话和 AI 计划收到训练档案。训练档案变化会使尚未保存的 AI 计划草稿失效，避免依据旧状态保存。

## 实时陪训

“结束本组”暂存检测次数；可连续检测多组。“结束训练并记录复盘”释放相机，打开整次确认页，并预建相应组数。

实验计次只显示为参考，实际次数、重量、RPE 不自动填写。只有用户确认后才成为正式训练。视频仍不录制、不上传；没有视频证据时，复盘不声称已经识别具体动作问题。

同一实时训练使用 capture ID 恢复本机草稿。已有其他未完成草稿时先处理该草稿，再返回陪训记录本次；不会覆盖旧草稿。整次检测结束后不可继续添加检测组，避免确认页与检测结果脱节。直接退出陪训前仍需点击结束训练进入确认页。

## 沉淀方式

- PostgreSQL `records.kind=workout` 按用户保存原始确认记录、日期、每组信息、用户感受、来源、计划快照、基础复盘及独立的 `ai_review` 和 `plan_progression`。SQLite仍可用于本地开发。
- `coach_profile.facts` 继续保存对话证据支持的基础事实和偏好。`GET /api/coach/profile.training_memory` 从持久记录生成动态训练档案，含来源记录 ID，不把 AI 建议写成用户事实。
- 不自动修改经验等级、训练限制、训练目标或 RM；训练量变化不证明力量提升。对比仅使用同一动作变式、相同负重口径及不晚于本次日期的历史。
- 有本次不适时提示暂停引起不适的动作；高 RPE 提示复核恢复、余力和负荷。独立进阶接口结合当前计划、画像、RM及不同日期的确认表现，核验后保存新的计划版本，展示下次目标及原因，可撤销最近一次调整。具体约束见 [AI计划](AI_PLANS.md)。
- 旧版单动作训练记录标为 `legacy` 并纳入档案。新记录同时写兼容历史行，带 `workout_id`；汇总时去掉这些兼容行，避免重复统计。旧版单动作记录不被伪装成包含整次细节的新训练。
- 本机未保存草稿存于 SharedPreferences `workout-draft-v1`。首次提交固定请求编号和内容；网络中断后使用同一编号重试，包括离开并重新进入页面。保存成功后清除草稿。

## 接口与模型

- `GET /api/workouts` → `{items, training_memory}`。
- `POST /api/workouts` → 确认一整次训练，含 `request_id`、`day`、可选用时、`exercises[].sets[]`、备注和来源。事务写入，拒绝未来日期、未知/自重动作、重复动作及无效组数值。同编号同内容返回原记录，不同内容返回409。
- `POST /api/workouts/{id}/review`，`{coach_id}` → 调用现有兼容模型服务，结合画像、动作库、RM、历史与当前记录，生成总结、本次完成情况、下次建议。结果成功后缓存；失败不写无效复盘、不删除原记录。若生成期间训练档案变化，返回409供重试。
- `POST /api/workouts/{id}/progression` → 根据关联的计划快照及实际完成记录判断下一次安排。结果缓存避免重复加重，变化存为新版本，原计划与训练事实均保留。
- 对话提示词版本 `coach-2.2`。计划模型输入新增 `training_memory`，仍遵循有效RM负荷校验。
- 复用 `.env` 的 `AI_API_KEY`、`AI_BASE_URL`、`AI_MODEL`，不需要新模型。没有密钥时仍有可用的记录、统计与基础复盘；AI 文案需要真实服务配置。

## 验证

后端测试覆盖事务、重复提交、日期与动作校验、训练统计去重、变式对比、旧记录兼容、复盘失败与缓存、聊天并发更新、计划草稿失效、进阶限制、版本冲突、撤销、周期推进及同日记录不重复进阶。Flutter测试覆盖首次引导、草稿需确认、多组确认、本机草稿恢复、固定编号重试、AI失败保留记录、实时计次必须确认。0.2.0已覆盖安装到荣耀手机并实际进入画像引导；真实AI生成、确认及首次训练后保持负荷在独立PostgreSQL数据库通过联调，未替用户填写健康数据。
