# 胸、背、腿力量画像与起始负重

2026-10-25按用户最新要求实现：生成计划前先把力量资料收齐；新AI周期不能用空重量交付。本页取代旧版“没有对应RM就置空重量”的规则。

## 用户操作

在“我”或首次画像引导中进入“力量评估”，再按胸、背、腿三个小组各选一个熟悉的动作。胸可选卧推、哑铃卧推、推胸机等，背可选划船、下拉等，腿可选深蹲、腿举、硬拉及支持的变式。填写近90天本人实际完成的一组重量、1–15次、主观还可完成0–5次、日期，确认重量口径及是否不适。无需专门测极限；不能填模型猜测或计划目标。90天是产品新鲜度规则，不是科学统一失效日期。

杠铃为含杆总重，哑铃为单只重量；高脚杯为单个哑铃或壶铃重量。器械需注明编号或名称，显示重量不跨器械直接比较。数据随“保存画像”提交，三部位缺失、日期无效或本组不适时显示具体问题并阻止完成引导及自动生成；本组不适请选当前可无不适完成的替代动作。

三块是粗略的产品参考方向，不是肌肉力量的单独测量；硬拉等动作不能精确代表整块腿肌力量。系统保留原始表现并向模型提供能力背景，不把所有动作换算成同一RM或用缺乏依据的“初/中/高级”统一分级。

## 计划与事实边界

- 同动作有效RM：继续使用原有负荷参考及上限；不能跨动作ID或口径套用。
- 同动作实际表现：首次建议不超过报告重量，同重量不要求更多次数；主观余力仍是用户自评，不自动转为RM。
- 其他动作：模型结合三部位表现、经验、器械及限制提出具体起始建议，服务端显示“部位力量参考估计 · 首训需校准”。没有固定跨动作比例，也没有证明跨器械重量等价。肩、臂等辅助动作的部位标签只表示背景来源，不表示已测到相应肌群力量。

新周期全部负重目标要求正数，空值、无效值、越过已有RM上限、不可用动作/器械、超时等结果拒收，提示重新生成。首训仍需逐步热身核对，用户可编辑目标并独立确认实际训练；没有自动首训校准器。初始建议的数值不保证适合所有个体，跨动作处方的专业质量尚未完成验证。原有自动进阶要求、恢复及不适门槛不放宽。

既有保存计划、RM与训练历史不重写。旧未启用AI草稿缺少力量修订，需要补齐资料后重新生成；修改力量资料或到期也使草稿失效。手工修改重量或次数的来源改成“用户确认的计划目标”，不变成实测依据。

## 接口与存储

`GET /api/strength-profile` 返回`ready/items/missing/options/revision`。`PUT`一次保存且仅保存胸/背/腿三项，字段为`region/exercise_id/weight_kg/reps/rir/measured_on/equipment_id/pain/confirmed`，同时提交`base_revision`；并发冲突409。缺失、重复部位、部位与动作错配、未确认、未来/过期日期、非有限数、器械缺标识均拒绝；包含不适的原始自报可通过API保存，但状态不ready，不能用于生成。

实现位于`backend/strength_profile.py`，复用owner隔离的`user_records`，`kind=strength_profile,id=current`；没有增加数据库迁移。动作器械/负重口径指纹、有效期、资料修订在生成前后和确认时检查。`load_reference`由服务端标注并保留；客户端自带来源字段不受信任。力量修订进入Agent上下文失效检查。画像基础字段与力量为两个独立API，力量先保存成功再保存基础字段；后者失败时可以重试，不自动生成计划。
